# PartsFlow

部品の発注・在庫管理業務を効率化するためのWebアプリケーションです。

製品の注文情報をもとに必要な部品数を計算し、現在庫と比較して不足部品・発注数量を確認できます。

また、発注・入荷・出荷・棚卸し・入出庫履歴までを一元管理することで、Excelや手作業で行っていた在庫管理業務の効率化を想定して開発しました。

## 開発背景

製造業における部品管理では、製品の注文数から必要な部品数を計算し、現在庫を確認したうえで不足分を発注する必要があります。

これらをExcelや複数の管理表で行う場合、

- 必要部品数の計算に手間がかかる
- 在庫数と発注数の確認が煩雑になる
- 入荷・出荷・棚卸しの履歴を追いにくい
- 転記や計算ミスが発生する可能性がある

といった課題があります。

そこでPartsFlowでは、製品注文から部品の必要数量・不足数量を自動計算し、発注から在庫管理までを一つのアプリで管理できる仕組みを実装しました。

## データベース

Supabase（PostgreSQL）を使用し、主に以下のデータを管理しています。

- ユーザー情報
- 製品マスタ
- 部品マスタ
- 製品構成（BOM）
- 製品注文
- 在庫
- 発注情報
- 発注明細
- 棚卸し
- 入出庫履歴

各データを関連付けることで、

**製品注文 → 必要部品計算 → 発注 → 入荷 → 在庫 → 出荷 → 棚卸し**

までの業務フローを一元管理できるようにしています。

---

## 工夫した点

### 1. 必要部品数・不足数量の自動計算

製品ごとの部品構成（BOM）と注文数量をもとに必要部品数を算出し、現在庫との差から不足数量を自動計算するようにしました。

```text
不足数量 = max(必要数量 - 現在庫, 0)
```

これにより、ユーザーが手作業で必要数量を計算する負担を減らしています。

### 2. 入荷・出荷・棚卸しを在庫と連動

単に在庫数を直接変更するのではなく、

- 入荷
- 出庫
- 棚卸調整

という在庫変動を履歴として保存する設計にしました。

これにより、「いつ・どの部品の在庫が・なぜ変化したか」を確認できます。

### 3. 二重処理・在庫不足への対策

入荷済みの発注を再度入荷したり、出荷済みの注文を再度出荷したりできないようにしています。

また、製品出荷時には最新の在庫数を確認し、必要な部品が不足している場合は出荷処理を中止するようにしました。

### 4. Supabase RLSによるアクセス制御

Supabase AuthとRow Level Security（RLS）を利用し、認証されていないユーザーから業務データへアクセスできないようにしています。
